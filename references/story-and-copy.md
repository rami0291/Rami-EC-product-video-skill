# 分镜、文案与节奏

本页写与语言无关的做法。每种语言的写法、排版、断行和阅读速度在 `references/locales/<locale>.md`；品类特有的用语和禁区在 `references/categories/`。

## 从卖点清单到故事

结构先在 [影片方向](direction.md) 里选定。"钩子 → 商品登场 → 卖点证明"是最常见的一种，品类笔记里还有更贴合各品类的结构。45–60 秒通常适合 3–4 个卖点、约 10–14 个镜头；这是容量参考，不是必须填满的模板。单一卖点的小配件可以 20–30 秒。

卖点从事实表里挑，按顾客的购买决策排序：**适不适合我（兼容 / 尺寸 / 肤质）→ 解决我的什么问题 → 做工和依据靠不靠谱 → 用起来方便吗**。不要按规格书的顺序念。

每个镜头在 `plan.json` 记录：起止时间、类型、各语言文案、卖点来源、商品素材、主要动作、声音提示。先估算阅读和演示时间（按最慢的语言版本），再贴合音乐节拍，不要先锁死 48 秒再塞文案。

以"钩子 → 证明"结构为例，可参考的段落：

| 段落 | 画面职责 | 节奏参考 |
| --- | --- | --- |
| 开场 | 痛点场景或商品最有辨识度的一面；3 秒内商品出现 | 2–4 秒 |
| 卖点证明 | 字卡提出卖点 → 商品特写 / 标注证明 → 使用或场景交代 | 每组 7–12 秒 |
| 细节快切 | 2–4 个做工 / 材质细节 | 每项 1.5–3 秒 |
| 规格 / 适配 | 尺寸、兼容、内容物 | 3–5 秒 |
| 落版 | 品牌 Logo + 商品名 + 一句收束 | 2–3 秒 |

镜头变化来自"要让观众看哪里"：整体、局部特写、标注、使用、场景、纯大字。不是用随机转场制造忙碌感。

## 多语言：一条时间线，多个语言版本

开工时问用户要做哪些语言（默认只做英语），以及每个语言版本发到哪个站点。答案写进 `plan.versions`：

```json
"versions": [
  {"id": "en-us", "locale": "en", "channel": "amazon-us", "accent": null},
  {"id": "ja-jp", "locale": "ja", "channel": "amazon-jp", "accent": "en"}
]
```

- **画面、时间线、配乐和音效所有版本共用**，只有屏幕文字随版本变化。每个镜头的文案按语言放在 `shot.copy[locale]`：`headline`、`description`、`plainExplanation`，有点缀语言时再加 `accent`（例如日文版上方的英文短标题）。
- **版式按最长的语言设计**。德语通常比英文长约 30%，法语长 15–20%；中日文字数少但字号要更大才同样易读。字号阶梯、标题列宽在最长版本里放得下才算定稿，不要为短语言定好版式后再把长语言硬塞进去。
- **镜头时长按最慢的语言定**。阅读时间不够时延长镜头或拆句，所有版本一起改。
- **每种语言单独写，不逐句翻译。** 先在事实表里写清白话事实，再用每种语言按其写法重写（transcreation）。数字、单位、认证用语从事实表抄，不从另一个语言版本转译。
- 图上文字（标注标签、规格表）同样按语言准备：`callouts.json` 的 `label` 写成 `{"en": "...", "ja": "..."}`。
- 品牌名、商品名、型号一般不翻译；注册商标的写法保持一致。
- 某个版本做不到时（例如没有该语言的字体授权），在 `typography.exceptionReason` 记录原话 / 依据，不悄悄换成别的方案。

## 文案要说人话

适用于所有语言：

- 标题可以短，说明不能只剩关键词。说明交代**对象 + 动作 + 可观察结果**，第一次看到的人也知道这件商品能做什么。
- 用目标顾客熟悉的词，不用内部型号代码和工厂术语；部件名、材质名、成分名与规格书一致。
- 不用无法证明的泛词（"更舒适""更高级""颠覆体验"），每种语言的常见泛词列在 `scripts/data/locales.json` 的 `vague`。
- 数字带单位，与规格书原文一致，不四舍五入。

| 过于省略 | 更清楚（前提是事实表里真有这些事实） |
| --- | --- |
| Rain? No problem. | Water-resistant zips and coated fabric keep your gear dry in sudden rain. |
| Charge faster. | One USB-C port delivers up to 65W, enough to charge a compatible laptop. |
| Skin, transformed. | A lightweight gel that leaves skin feeling hydrated without stickiness. |

各语言的对照例子见对应的语言笔记。

## 主标题与点缀语言

有点缀语言（`accent`）的版本：点缀负责提炼卖点 / 动作，主语言负责让人直接理解。两者都在主要视觉层级。

- 主语言和点缀语言各自独立 span，设 `lang` 属性，在 `typography.fonts` 分别指定字体。**不是让 fallback 随机分配字形。**
- 点缀必须贴合卖点，不机械翻译主语言长句，不为了排版硬塞无关口号；没有点缀，主语言也要能独立理解。
- 不是每一个标注都要双语。
- 字体来自品牌或有授权的字体；正式工程把字体文件放进 `assets/fonts/` 并查看实际字形，不能仅凭 CSS 字体名判断已加载。

## 文案试读：有句号也可能仍然是空话

每个语言版本按卖点逐项执行，写入 `evidence/copy-review.md`：

1. 先写白话事实："顾客以前遇到什么麻烦，用了这件商品怎么做，结果有什么不同。"只写有来源的部分；不知道就不编造对比。
2. 从中提炼标题，再写说明。说明必须交代对象 + 动作 + 可观察结果，必要时补使用场景；长度以讲清楚为准。
3. 遮住画面和点缀语言，只读主语言给没用过这件商品的人听。若仍需要问"装在哪 / 怎么用 / 能做到什么"，重写。可以的话请该语言的母语者读一遍。
4. 检查标题与说明是否只是同义重复；说明应补充用法或结果，而非再次赞美商品。
5. 对照该版本的渠道笔记和品类笔记，把禁止与慎用表达过一遍。
6. 用自然语气朗读，再检查字幕显示时间。不要以"字数够了""有句号"代替内容审查。

`plainExplanation` 存放按事实写的白话解释；`description` 是最终上屏文字。两者可相同，但不能为了"高级感"把具体解释重新压成抽象短语。脚本只能发现缺字段和部分可疑措辞，语义是否清楚仍须上述试读。

## 动作、停留与音乐

- 入场 / 落定 / 扣合动作通常 0.25–0.6 秒；让动作有明确起止。
- 每个镜头一般安排"建立画面 → 核心动作 → 可读结果 → 切走"，不要全部元素一起飘入再静止 5 秒。
- 说明文字早出现，让阅读时间与商品演示重叠。长句不靠缩字号解决，优先删冗词、分句或增加停留。
- `check_delivery.py` 按每种语言的阅读速度给出提示（CJK 按字 / 秒，拉丁语系按含空格字符 / 秒，数值见 `locales.json`）。画面同时有复杂变化时还要留余量；这是人工阅读的起点，不是通过阈值。
- 编曲速度按方向文件的声音轴选，拍点约为 `60 / BPM` 秒，主动作贴重拍，小动作错开半拍。不要把所有片段硬量化成同一长度。
- 空白或完全静止并非一概错误：短暂停顿用于强调 / 阅读。警惕无信息的长停顿；不要为了消除静止检测加入无意义晃动。
- 结尾要有完整落版与声音收束：品牌 Logo、商品名和一句结束语。

## 静帧审阅

从实际代码截取代表镜头，**每个语言版本各出一组**，按播放顺序排成联系表。核对是否有画面尺度变化、是否一眼知道主次、缩小到手机宽度能否读懂说明，以及各语言的断行问题（见对应语言笔记）。静帧通过只能证明布局方向；节奏、动作连贯和声音仍需看成片，方法见 [审片](review.md)。
