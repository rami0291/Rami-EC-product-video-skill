# 案例复盘：保留做法，不固化偶然参数

## 迭代中真正修过的问题

| 问题 | 根因 | 可复用的检查 |
| --- | --- | --- |
| 画面好但像无声 | 早期音乐过轻，存在音轨仍听感不足 | 测响度并试听成片 |
| 节奏像卡住 | 重复布局，动画和静止停留偏长 | 提前给说明、穿插字卡和特写、让每次停顿有信息 |
| 方向稿偏离用户意思 | 生成概念图不能代替真实素材做的画面 | 早期就用真实照片出静帧，方向稿也来自实际渲染 |
| 放大后元素下沿被裁 | 定位偏移叠加缩放，超出局部遮罩 | 检查变换后的边界，居中并预留空间 |
| 独立预览里图片裂图 | 引用了网站根路径，独立预览资源缺失 | 资源复制进工程并用相对路径，预览与导出分别验图 |
| 字少但说不清楚 | 小字只有短语，没有对象与结果 | 完整句子，提早出现，按阅读时间安排镜头 |
| Logo 不完整 | 只用了图标中心符号 | 用正式完整的 Logo 文件 |
| 抽帧缺元素 | CSS transition 与主时间线争夺状态 | 冻结 CSS 动画，全部动画接到主时钟，前后 seek 验看 |
| 不符合发布要求 | 画面和片尾有 URL | 去掉 URL，素材里的网址遮挡，移除片尾链接及对应动画 |

静帧检查不能替代看节奏；脚本检查通过不能替代成片检查。

## 模型一口气出片的结果很差

让模型直接从素材一路做到渲染好的 MP4，结果很不如人意。正确做法是初期降低 effort，多加人工判断，特别是在模型理解商品的正确用法、安装位置和尺寸之前：先确认事实表和方向，再出几张静帧给用户看，然后才做全片。

## 清单式迭代为什么变差

同一个产品做过三版，对照很说明问题：

| 版本 | 做法 | 结果 |
|---|---|---|
| 先写规范再做 | 先写视觉规范（字号阶梯、上镜尺寸、边距、安全区），再给每个镜头写一份详细镜头说明，最后用 GSAP 逐镜头编排 | 节奏好、画面精细、文字动效到位 |
| 按"12 个蓝图 + 动效原语 + 落拍/静止帧指标"迭代 | 每个镜头套一个蓝图名，用统一的入场，靠指标验收 | 29/29 动作落拍、切点全在小节线上；画面却挤、字小、标题撞图标、大片空白 |
| 本 skill 当前流程 | 先写 `DIRECTION.md`（参考拆解、商品气质、三个方向、画面规范、镜头表），逐镜头出静帧，全片出联系表和转场条带 | — |

教训：**模型会去满足能量化的东西。** 把"好看"压缩成蓝图名和指标，就会得到指标完美、画面平庸的片子。让质量落地的是写代码之前的设计：规范写成具体数字，镜头写到每一秒。

## 推导示范

商品的推导过程，只用来说明"因为商品有 X，所以用 Y"怎么写。

商品（摩托车周边品类，日文版）：防水シートバッグ（规格书写明：止水ファスナー、TPU コーティング生地、容量 30L→40L 拡張、付属ベルトで工具不要取付）。

| 手法 | 因为商品有…… |
|---|---|
| 开场是雨天停车场，普通背包被淋湿的瞬间定格（痛点切入）| 目标顾客是通勤和ツーリング骑手，雨天行李湿是真实痛点 |
| 水珠粒子沿面料滑落，止水拉链拉合时配清脆的拉链声 | 止水ファスナー和 TPU 生地有规格依据 |
| 拉链展开，容量数字 30L → 40L 滚动 | 拡張ファスナー，数字来自规格书 |
| 安装三步实拍硬切，每步一个织带拉紧声 | 工具不要取付，步骤与说明书一致 |
| 落版用品牌 Logo 遮罩转场 | 品牌 Logo 是简单几何形 |

手机支架的推导应从"减轻振动对手机的损害"和"可视角度"出发。
