# 商品与品牌审计

先读本片品类的笔记（`references/categories/<category>.md`）：它列出这个品类事实表要补的字段、必须有出处的说法和禁区。本页写所有品类通用的做法。

## 商品事实

先读素材目录里的规格书、说明书、成分表、测试报告、商品页文字（标题、要点、商品说明），再看照片。不要凭照片猜材质、尺寸或成分，也不要从竞品页面借数字。

把结果写进 `evidence/product-facts.md`（初始化时已按品类生成表头），每项写：

| 字段 | 含义 |
| --- | --- |
| 项目 | 商品名 / 型号、尺寸、重量、材质、内容物、使用方式、颜色，加上品类笔记要求的字段 |
| 内容 | 原文照录（单位、原文语言一起抄），不四舍五入、不换算后再上屏 |
| 来源 | 素材目录相对路径 + 页码 / 行号，如 `product:spec/spec-sheet.pdf#p2`；用户口头提供的写"用户确认（日期）" |
| 能否上屏 | 能 / 只能写进说明 / 不能（无出处、内部资料、与其他资料矛盾） |

资料之间有矛盾就问用户，不自己挑一个。各语言版本的数字都从这张表抄，不从另一个语言版本转译。

几类说法要格外小心（各品类的具体项目见品类笔记）：

- **适配 / 兼容**：只写资料列出的车型、设备、肤质；"通用""兼容大多数"要有资料依据，并把适配条件一起写清。
- **认证与性能**：必须有测试报告、认证编号或规格书原文。只有"防水仕様"的，不要升级成"完全防水"或"IP67"。认证按市场生效：一个市场的认证不等于另一个市场合法。
- **原厂 / 官方 / 授权**：没有授权就不暗示与别的品牌有合作。
- **使用限制**：要专业安装、需要另购部件、特定条件下不能用。方向和文案不能与之矛盾。

用户说"突出某个卖点"，先确认事实表里有支撑；没有就告诉用户缺什么资料，不要先写进文案。

## 照片审计

逐张列在 `evidence/asset-usage.json`（字段见 [素材处理](asset-pipeline.md)），先回答：

1. 有哪些角度：正面、侧面、背面、细节（缝线、接口、质地、刻印）、内容物平铺、使用中的照片、场景照。
2. 每张的像素尺寸和清晰度：能放大到多大（见素材处理里的放大上限）。
3. 有没有透明底 PNG 或干净白底，可以直接抠。
4. 场景照里有没有第三方 Logo / 商标、个人信息（车牌、屏幕通知、住址）、未授权的人脸。
5. 各颜色 / 型号 / 色号是不是都有实拍；没有实拍的，片子里就不出现。

## 品牌审计

在 `evidence/style-audit.md` 写出：

1. 品牌资产：Logo（横版、方形、单色版的适用范围）、品牌色（HEX 值和来源文件）、包装 / 吊牌 / 官网 / 既有 Amazon A+ 页面上用过的字体和排版，以及**各语言的品牌字体**（品牌的拉丁字体往往没有中日文字形）。素材里没有就问用户要，不自己仿制 Logo。
2. 品牌调性：目标顾客是谁，品牌在已有素材里给人的感觉（硬派、实用、精致、亲和、专业、俏皮）。不同市场的品牌调性如果本来就不同（例如日本站更亲和），按品牌已有素材走。
3. 商品本身的视觉特征：主色、材质、表面（哑光、亮面、拉丝、透明）、形状语言（圆润、棱角、管状）。
4. 母题候选：能直接变成画面的商品元素，是 [影片方向](direction.md) 推导专属手法的原料。品类笔记列了各品类常见的来源。
   - 外形轮廓与结构
   - 材质、质地与工艺
   - 使用动作
   - 使用位置与场景
   - 品牌名或商品名的字面意象
5. 决策：brand / default / hybrid，理由与保留的品牌识别点。

"品牌素材不好看"要变成可操作的判断：层级混乱、字号 / 间距不一致、对比不足、信息太密、照片光线不统一。不要把自己的审美偏好当成客观结论，也不要背着用户换掉品牌色或 Logo。

## 三种风格的范围

- `brand`：按品牌审计结果制作，品牌色、字体、Logo 都来自品牌自己的资产。
- `default`：品牌素材不全或用户想要统一的外观时，用中性包装：深炭灰或浅水泥灰底、单一强调色（从商品主色里取，不是固定色）、无衬线大字，各语言分别配字体。只负责字卡、背景和外层排版；商品本身的颜色和外观不改。
- `hybrid`：保留品牌 Logo 和品牌色作为识别点，外层排版、节奏和背景为传播重新设计。

不要把用户素材目录里的客户信息、进货价、内部备注、未公开的新品资料复制进可分享的工程。
