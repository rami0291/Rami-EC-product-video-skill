# 素材处理：从商品照片到可渲染画面

## 原则

商品画面只用真实照片。可以做的：裁切、抠图、去除灰尘和背景杂物、统一曝光和白平衡、加投影、拆层做视差、加光效叠层、加标注线。不可以做的：改变商品的颜色/形状/纹理、补画照片里没有的部件、用 AI 生成"另一个角度"、把没有实拍的颜色调色出来冒充、用 AI 放大给细节镜头"补"纹理。

背景、天空、路面这类氛围层可以用授权素材或合成，但商品与背景的组合不能让人误解商品的实际状态（例如把室内样品图合成到暴雨里，暗示有没被证明的防水性能）。合成的使用场景在 `asset-usage.json` 标明，必要时画面角落加对应语言的说明（`locales.json` 的 `disclaimer`：Image for illustration purposes only. / ※画像はイメージです / Symbolbild / Photo non contractuelle / 图片仅供参考）。

## 素材进工程

素材目录只读。用到的照片复制到视频工程 `assets/photos/`，处理结果另存，不覆盖原图：

```
assets/photos/original/   从素材目录复制的原图（保留原文件名）
assets/photos/cutout/     透明底 PNG
assets/photos/graded/     调色、去杂物后的版本
assets/brand/             Logo（SVG 优先）、品牌字体（确认授权）
```

## 放大上限

画面里商品显示的像素尺寸不要超过原图对应区域的像素尺寸。粗略换算：

- 商品在原图里占 W 像素宽，画面里显示宽度 ≤ W（1080p 下）；细节镜头裁出的局部同理。
- 超过 1.0 倍：边缘发软，宽度 1920 的画面里看得出来；最多到 1.2 倍且只用于运动中的镜头。
- 细节/微距镜头需要原图本身就是近拍或高分辨率（4000px 以上）；没有就向用户要，或改成不需要那么近的镜头。
- 推近动画的终点按上限算，不按"好看"算。

## 抠图

1. 优先用用户提供的透明底 PNG 或白底原图。
2. 需要自己抠时：用 rembg 等本地工具或图像软件，结果放 `cutout/`。在深色和浅色背景上各看一次边缘（200% 放大）：白边、毛边、缺角、把阴影或吊牌一起抠进来都要修。
3. 抠完加贴地投影（contact shadow）：一层模糊的椭圆暗影，跟随商品位置移动。浮空镜头的投影要随高度变淡变大。
4. 带透明部件、网眼、细绳的商品，抠图最容易出问题，镜头尽量避开需要大面积干净边缘的取景。

## 实装照与场景照

- 第三方 Logo、徽标、商标（宿主车辆、手机、电脑、别家商品）：裁掉、虚化或压暗到不可辨认（[视觉手法词汇](visual-vocabulary.md) 的"实装 / 使用场景"）。
- 个人信息：车牌、门牌、屏幕上的通知 / 联系人 / 地图位置，完全遮挡；遮挡层随镜头一起移动和缩放，在每一帧都盖住。
- 人物：有使用许可（覆盖电商视频和所有上线市场）才出现可辨认的脸；否则只拍手、背影。
- 宿主物件（车、手机、电脑）是别人的设计，不做画面主角；镜头聚焦商品，宿主可降低饱和度和亮度。
- 各品类的具体风险（车牌、屏幕内容、美妆前后对比）见品类笔记。

## 2.5D 与光效

照片是平的，镜头运动要在"看起来立体"的范围内：

- **视差**：把商品、地面阴影、背景拆成 2–4 层，按深度给不同的位移速度。移动幅度小（画面宽度的 2–5%），太大就露出平面感。
- **小角度倾斜**：Three.js 平面贴照片或 CSS `perspective` + `rotateY`，角度 ≤ 8°；超过就能看出是纸片。
- **光泽扫过**：在抠图上叠一层渐变高光（`mix-blend-mode: screen/overlay`，用抠图的 alpha 做遮罩），模拟灯光扫过。只用于亮面、金属、阳极氧化这类真的会反光的材质；哑光尼龙、皮革不要加镜面光。
- **伪旋转**：只有一组连续角度的实拍（360° 转台照）才能做旋转；用两三张不同角度硬切或遮罩切换，不要做插值变形。

## 标注与规格数据

规格标注（引出线、尺寸线、材质标签）的位置写进 `src/fixtures/callouts.json`，坐标用**照片的归一化坐标**（0–1），由运行时换算到屏幕，这样照片缩放/移动时标注跟得上：

```json
{"photo":"assets/photos/cutout/bag-side.png","callouts":[
  {"id":"zip","at":[0.62,0.18],"factRef":"material-zip",
   "label":{"en":"Water-resistant zip","ja":"止水ファスナー","de":"Wasserabweisender Reißverschluss"}},
  {"id":"width","from":[0.05,0.92],"to":[0.95,0.92],"factRef":"size-w",
   "label":{"en":"Width 400 mm","ja":"幅 400mm","de":"Breite 400 mm"}}]}
```

`factRef` 指向事实表里的项目；标签文字和数字从事实表抄，不手写近似值。`label` 按语言版本各写一份，运行时按当前版本的 `locale` 取；最长的语言（通常是德语）也要放得下，必要时让标签换行或换锚点方向。

## 每个商品镜头的素材证据

在 `evidence/asset-usage.json` 逐镜头记录：`shotId`、`asset`（工程里用到的文件）、`original`（素材目录里的原图路径）、`processing`（裁切/抠图/调色/去杂物/合成背景）、`sourcePixels` 与 `displayPixels`、`composite`（是否合成场景）、`masks`（Logo / 个人信息遮挡）、`license`（用户提供 / 素材站 + 许可）。

清单和静帧要对得上：静帧里出现的每个商品画面都能在清单里找到原图。合成或做过较大处理的镜头明确标注，不把整片笼统称为"全部实拍"。

## 资源与确定性

- 等字体和图片解码完再截图：`await document.fonts.ready`，图片检查 `img.complete && img.naturalWidth > 0`。
- 本地 HTTP 服务比 `file://` 更接近导出环境；最终导出不依赖外网。
- 大图先缩到需要的最大显示尺寸的 1–1.5 倍再进页面，过大的原图会拖慢每帧截图。
- 随机数固定种子；所有动画由同一条主时间轴或纯 `seek(t)` 驱动（见 [渲染管线](render-pipeline.md)）。

## 链接与文字

按发布渠道处理，Amazon 各站点都不出现 URL、QR 码、店铺名以外的联系方式（见 [Amazon 通用](channels/amazon-common.md)）。照片里如果有吊牌、包装上印的网址，裁掉或遮挡，并在缩放移动中一直盖住。
